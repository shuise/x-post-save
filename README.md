# 资源下载

这是一个 chrome 插件，用于把 X（Twitter）上点赞的推文批量下载到本地。

## 基础信息
- 插件名称：小蜜蜂，![](logo.jpg)
- 插件版本：1.0.0
- 插件作者：shuise
- 插件描述：批量下载 X 点赞推文及其图片、视频，并取消已下载推文的点赞

## 下载源 https://x.com/i/history/likes
1. 下载所有点赞的 tweet，注意分页问题
2. 下载时包含图片、视频、音频等资源
3. 每一个 tweet 对应一个 md 文件，内容为 tweet 的内容，把图片视频等作为附件下载并引入到 md 文件中
4. 下载完后，取消点赞，避免重复下载
5. 下载存储到 `/Volumes/LaCie/x-medias`

## 安装
```bash
npm install
npm run build      # 产物在 dist/，构建末尾会自动跑 tsc --noEmit
```
打开 `chrome://extensions` → 开启「开发者模式」→「加载已解压的扩展程序」→ 选中 `dist/` 目录。

## 使用
1. 在浏览器里登录 X，打开 https://x.com/i/history/likes
2. 点插件图标 →「打开任务面板」
3. 面板里依次点「选择目录」→「开始扫描」→「开始下载」→「开始取消点赞」

**任务期间请保持点赞页标签页为当前标签页，不要切换或关闭它** —— 页面用的是虚拟滚动，标签页在后台就不会继续渲染新条目，扫不到东西。任务面板本身是独立窗口，可以失焦，但不能关。

## 选中文字工具

在任意页面选中文字 → 右键，有两个菜单项：

| 菜单项 | 去向 |
|---|---|
| 生成卡片 | https://note-card-mauve.vercel.app/ 渲染成卡片（只渲染，不下载） |
| 注音 | https://pinyin-annotator.tjsky.net/pinyin 加拼音／注音 |

目标页**已经开着就复用那个标签**并重载（各自复用各自的），不会每点一次堆一个新标签。

之所以要绕这么一圈：这两个站都没有「从 URL 读文本」的入口（note-card 只认自己的 localStorage 和输入框；注音工具的 URL 参数只有 `?v=` 选版本），所以文字塞不进地址栏。实际链路是先写 `chrome.storage.local`，再由 `inject-text.js` 内容脚本取出来写进目标页的输入框，写完即清。

- 内容脚本只在上面两个域名上运行，且只在确实有待处理文字时才动手；你自己打开这两个页面不会被干扰
- 输入框是受控组件，直接赋 `.value` 不会触发框架重渲染，所以走「原型原生 setter + 冒泡 `input` 事件」
- 注音工具的输入框没有可依赖的 id（它是一整个 1.37MB 的单文件页面），按「可见 textarea 里最大的那个」来认；找不到就只打一条警告，文字留着下次再试

## 输出结构
```
/Volumes/LaCie/x-medias/
├── 今天看到一只很可爱的猫.md        # 一个推文一个 md，直接放在根目录
├── 关于分布式锁的一些想法.md
├── 2024-03-11_1767098765432109876.md  # 正文为空时的兜底名
├── assets/
│   ├── 1767098765432109876_1.jpg
│   ├── 1767098765432109876_2.mp4
│   └── 1767098765432109876_2_poster.jpg
└── _bee/
    ├── ledger.json              # 断点续传账本
    ├── report.json              # 本轮统计
    ├── skipped.md               # 跳过清单（含原因与原始地址）
    └── unparsed.json            # 解析失败的结构 dump，X 改版时用来定位
```

md 文件名取自**推文正文的第一段话**：只保留字母、数字、空格、`_` 和 `-`，其余字符（含 emoji 与 `/ \ : * ? " < > |`）一律去掉，长度上限 60 个字符；两段话同名时在后面补推文 ID。正文为空或整段被过滤空时，退回 `日期_推文ID` 这种兜底名，绝不产生无名文件。

所有附件统一放 `assets/`，文件名是 `<推文ID>_<序号>.<扩展名>`，靠推文 ID 前缀保证全局唯一（不这么做的话，不同推文的第一张图会互相覆盖）。

**日期固定用 `Asia/Shanghai` 时区**（因为你在 X 界面上看到的就是本地时间）。这个选择是固定的，否则跨时区重跑会产生两套目录名。

## 关于存储路径
`/Volumes/LaCie/x-medias` 这个绝对路径**无法由插件自己指定** —— Chrome 扩展读不到也探测不到任何绝对路径，`chrome.downloads` 也只认下载目录内的相对路径。所以走的是 File System Access API，由你在面板里手动授权一次：

- 可以直接选中 `LaCie` 盘，插件会在其中创建 `x-medias`
- 也可以直接选中已有的 `x-medias` 目录
- 授权句柄保存在 IndexedDB 里，浏览器重启后权限可能回到「需要确认」，面板上点「重新授权」即可
- 目标目录是否可用，靠写一个 `.bee-check` 探针文件再删掉来判定

macOS 上如果选择器里看不到移动盘，检查「系统设置 → 隐私与安全性 → 文件与文件夹 → 可移动卷」是否放行了 Chrome。

## 断点续传
账本记录在 `_bee/ledger.json`（运行时以 IndexedDB 为准并导出）。

**`done` 的判定是「md 文件写成功」，而不是「媒体下完了」。** md 是最后一步写的，它存在即代表这条完整。这样外置盘掉线导致的写失败不会污染账本：md 没写成功，记录就停在 `pending`/`partial`，重跑会重做这一条；媒体重写是幂等的。

媒体**全部**失败的推文也会写 md（正文、原推文链接和失败原因都留在文件里，front matter 里 `state: failed`），不会因为附件拿不到就整条消失。失败原因带具体状态码，例如 `视频下载失败（HTTP 403）：1767_1.mp4`。

拔盘、关任务窗、service worker 被回收，三种中断都不会丢进度或重复下载（已完成的推文不重复下载）。

## 风险告知
- 批量取消点赞是唯一会对账号产生副作用的动作。**可能触发账号限流或临时锁定**，工具会在检测到限流（HTTP 429 / GraphQL code 88）时退避或暂停整个阶段，但风险仍然由你自行承担。
- X 的服务条款反对此类自动化操作，请自行评估。
- 取数方式是监听页面自身发出的 GraphQL 响应，不伪造鉴权头、不重放请求；取消点赞走真实 DOM 点击，让 X 自己的代码路径完成。

## 技术说明
- Chrome 扩展 Manifest V3，`minimum_chrome_version: 116`
- MAIN world 注入脚本只做「patch fetch/XHR + 搬运响应」，不做任何解析；解析与 DOM 操作在 ISOLATED world
- 媒体下载只在扩展页里做（内容脚本的跨域请求受页面 CORS 约束）
- 视频优先取最高码率 mp4；没有 mp4 变体时才做极简 HLS 合并（X 用 fMP4 分片，直接拼接即为合法 mp4），HLS 失败或加密不支持会进跳过清单，不阻塞整体
- 媒体下载并发按最重的媒体项定：带视频的推文串行下载，纯图片推文 3 路并发（X 的 CDN 按账号/IP 限流，视频是 429 的主要来源）
- 命中 429 时尊重响应的 `Retry-After`（秒数或 HTTP-date 两种写法），并且是**全局**退避——限流按账号算，让单条自己重试只会把窗口越撞越长。退避超过 2 分钟则放弃该条并记原因，不让任务卡住；退避过程会打进任务面板日志

### 抓包定标（可选）
`scripts/capture-snippet.js` 是一个 DevTools Snippet，用来在真实账号上核对 X 的响应形状。X 改版导致解析失效时，用它导出新的 fixture 放进 `tests/fixtures/captured/`。
